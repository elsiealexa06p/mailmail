{# Auto-Refresh — bleibt aufklappbar weil es ein eigener größerer Block ist #}
🔄 Auto-Refresh + Health-Adaptive Weights {% if c.get('auto_refresh_enabled') %}ON{% endif %}
Alle N Sends werden im Hintergrund neue Varianten generiert und parallel zu Cloudinary + AWS-Buckets hochgeladen + neue CID-Files geschrieben. Failt eine Quelle (z.B. Cloudinary down), wird deren Anteil in der Meta-Rotation automatisch runtergedreht. Wenn alle Cloud-Uploads scheitern → CID-only. Wenn CID auch dead → alte Variants (letzter Fallback).
Standard: 100.000. Zu niedrig = zu viel AWS/Cloudinary Upload-Traffic.
Standard: 1000. Wird gleichmäßig auf CID + Cloudinary + alle S3-Buckets verteilt.
Weight-Multiplikator. 1.0 = CID/CDN gleich wahrscheinlich. 3.0 = CID 3× so oft wie CDN (Default, weil CID am robustesten). 5.0+ = CDN nur selten.
Zusammenspiel:
Meta-Rotation → welche Modi überhaupt gewürfelt werden.
Auto-Refresh → hält Assets frisch + baut Weights.
Kaskaden-Fallback → wenn Modus stumm, silent zu CID.

{# ── Section 2: HTML-Modi + Anti-FP ── #}
HTML-Modi + Anti-FP Feintuning
{% if c.get('live_html_gen_enabled') %}Live-Gen ON{% endif %} {% if c.get('assembly_mode_enabled') %}Assembly ON{% endif %}
Standard: Kampagne wählt pro Send ein Template aus dem vorhandenen HTML-Pool (siehe Config → freshness_html_count).
Live HTML Gen: pro Send erzeugt die htmlgen-Engine live ein frisches Template (mit Macros wie {Satz1}, {Ende}, {Footer1} die dann normal aufgelöst werden). Kein Pool nötig, maximale Variation pro Empfänger, ~5ms Overhead pro Send.
Assembly: Snippet-Pool-basiert (/snippets) — Alternative wenn du eigene HTML-Fragmente pro Slot pflegen willst.
Priorität: Live-Gen > Assembly > Pool.
Leer = htmlgen wählt pro Mail eine Farbe aus dem Standard-Pool (4 Blau-Töne für primary, 3 Rot-Töne für accent — konfiguriert in htmlgen/config.yaml). Gesetzt = alle Mails dieser Kampagne nutzen diese Brand-Farbe konsistent.
Pro Send zusätzlich zufällig:
• 15% Referenz-Block komplett raus
• 15% Hinweis-Block komplett raus
• 20% Footer2 leer (nur Footer1 sichtbar)
• 25% FristText1 ↔ FristText2 vertauscht
Alle Ereignisse unabhängig. Test-Modus — wenn alles gut aussieht, macht's Sinn die Raten irgendwann fest zu verankern.
Anteil an Mails die KOMPLETT unbearbeitet raus gehen. Default 0.02 = 2%.
Anteil mit nur subtilen Transforms (kein Tag-Swap, keine Class-Inject). Default 0.10 = 10%.
Rest der Mails bekommt volle Anti-FP-Behandlung. Verteilung natürlich: manche Mails „sauber", andere „leicht verändert", die meisten „durchgeschüttelt".
